Лабораторная работа №1 — архивирование старых файлов

Проект команды из трёх человек. Мы разрабатываем Bash-скрипт для архивирования старых файлов при превышении заданного порога заполнения, автоматические тесты для него и версию основного скрипта для Windows.

## Участники и задачи

| Участник | Задача | Файл |
| --- | --- | --- |
| Участник 1: имя или GitHub-аккаунт | Основной Bash-скрипт, включая режим LZMA | `archive_logs.sh` |
| Участник 2: имя или GitHub-аккаунт | Автоматическая подготовка тестовых данных и проверка Bash-скрипта | `test_archive.sh` |
| Участник 3: имя или GitHub-аккаунт | Основной скрипт для Windows и его ручная проверка | `archive_logs.bat` |

Перед сдачей каждый участник должен уметь объяснить общую логику проекта и запустить свою часть.

## Требования лабораторной

Основной скрипт получает путь к папке с файлами и порог `X` в процентах. Он сообщает процент заполнения папки. Если порог превышен, скрипт выбирает самые старые файлы по дате изменения, создаёт архив в папке резервных копий и удаляет исходные файлы после успешного архивирования. Скрипт должен выводить понятные сообщения о своих действиях.

Обычный формат архива — `tar.gz`. Если установлена переменная окружения `LAB1_MAX_COMPRESSION=1`, Bash-скрипт использует LZMA; для этого режима нужен отдельный тест.

Проверяющий Bash-скрипт самостоятельно подготавливает тестовые данные, запускает основной скрипт и проверяет результаты. На слайде требуется не менее четырёх тестов, а на фотографии доски указано пять, поэтому команда планирует **не менее пяти обычных сценариев и отдельную проверку LZMA**. В каждом тестовом сценарии папка с файлами должна занимать не менее **0,5 ГБ**.

Для Windows планируется основной скрипт `.bat`. Отдельный проверяющий `.bat` пока не входит в план команды.

## Соглашения, которые нужно утвердить до написания кода

В исходных материалах не определено, относительно чего считать «процент заполнения папки». Команда должна выбрать одно точное правило, согласовать его для Bash- и Windows-версий и записать здесь **формулу и пример расчёта**. При возможности этот вопрос следует уточнить у преподавателя.

**Процент заполнения:** решение пока не принято.

**Аргументы и порядок запуска:** решение пока не принято. Нужно определить путь к исходной папке, порог и способ указания папки для архивов. Путь к архивам желательно делать настраиваемым, чтобы тесты не затрагивали системные папки.

**Область поиска файлов:** решение пока не принято. Нужно указать, обрабатываются ли вложенные папки.

**Имена архивов и действия при ошибке:** решение пока не принято. Исходные файлы можно удалять только после успешного создания архива.

После согласования этих пунктов замените строки «решение пока не принято» конкретными правилами. Только затем участники смогут независимо писать скрипты и тесты по одному интерфейсу.

## Запуск

Команды запуска Bash-, тестового и Windows-скрипта будут добавлены после утверждения аргументов и появления работающих версий.

## План проверок

1. Порог не превышен: файлы остаются на месте.
2. Порог превышен: создаётся архив, исходная папка уменьшается.
3. Выбираются самые старые по дате изменения файлы.
4. Переданный порог влияет на результат.
5. Ошибочный путь или другая согласованная ситуация обрабатывается безопасно.
6. Отдельный сценарий для `LAB1_MAX_COMPRESSION=1`: проверяется формат архива и возможность извлечения файлов.

Окончательные проверки должны сравнивать фактические файлы и содержимое архива с ожидаемыми, а не только смотреть на сообщение скрипта. Windows-версия пока проверяется вручную.
